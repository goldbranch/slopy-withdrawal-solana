# Slopy Withdrawal Solana

Безопасная программа для обработки выводов средств в сети Solana с проверкой подписей сервера и управлением одноразовыми номерами (nonce) для предотвращения атак повторного воспроизведения.

## Обзор

Программа обеспечивает доверенный вывод токенов с использованием:

- Проверки ECDSA подписей secp256k1
- Защиты от повтора запросов через nonce
- Временных ограничений на запросы
- Валидации адреса получателя
- Управления хранилищем через PDA (Program Derived Address)

## Особенности

1. **Проверка подписи сервера**  
   Для вывода требуется валидная подпись secp256k1 от предварительно настроенного серверного ключа

2. **Защита от повтора**  
   Уникальные одноразовые номера (nonce) хранятся в состоянии программы

3. **Временные ограничения**  
   Запросы истекают через 150 слотов (~3 минуты при 400 мс/слот)

4. **Проверка получателя**  
   Гарантирует отправку токенов только на авторизованные адреса

5. **Автоочистка nonce**  
   Старые nonce (старше 150 слотов) автоматически удаляются

## Требования

- Anchor v0.30.0+
- Solana CLI v2.1.15+
- Rust 1.85.0+

## Начало работы

### Установка

```bash
git clone https://github.com/goldbranch/slopy-withdrawal-solana.git
cd slopy-withdrawal-solana
anchor build
```

### Развертывание

1. Обновите ID программы в `declare_id!` и `Anchor.toml`
2. Деploy программы:
   ```bash
   anchor deploy
   ```
3. Инициализация состояния:
   ```rust
   let server_pubkey = /* 64-байтный публичный ключ secp256k1 */;
   await program.methods.initialize(server_pubkey)
     .accounts({ /* аккаунты */ })
     .rpc();
   ```

## Использование

### Инициализация

Инициализируйте программу с публичным ключом сервера:

```rust
pub fn initialize(ctx: Context<Initialize>, server_pubkey: [u8; 64]) -> Result<()> {
    ctx.accounts.state.server_pubkey = server_pubkey;
    Ok(())
}
```

Необходимые аккаунты:

- `state` – Аккаунт состояния программы
- `vault` – PDA-хранилище токенов
- `authority` – Администратор

### Процесс вывода

1. **Запрос клиента**  
   Сформируйте сообщение для вывода:

   ```rust
   struct WithdrawMessage {
       nonce: u32,
       amount: u64,
       recipient: Pubkey,
       slot: u64,
   }
   ```

2. **Подпись сервера**  
   Сервер подписывает сообщение приватным ключом:

   ```javascript
   const message = serializeWithdrawMessage(nonce, amount, recipient, slot);
   const signature = secp256k1.sign(keccak256(message), privateKey);
   ```

3. **Отправка клиентом**  
   Отправка запроса с подписью:
   ```rust
   await program.methods.withdraw(
       nonce,
       amount,
       recipient,
       slot,
       signature,
       recoveryId
     )
     .accounts({ /* аккаунты */ })
     .rpc();
   ```

### Ключевые аккаунты

- `state` – Хранит серверный ключ и использованные nonce
- `vault` – PDA-контролируемое хранилище токенов
- `recipient_token_account` – Предварительно проверенный аккаунт получателя

## Коды ошибок

| Код | Название                 | Описание                          |
| --- | ------------------------ | --------------------------------- |
| 0   | InvalidSignature         | Неверная подпись сервера          |
| 1   | ExpiredWithdrawalRequest | Просроченный запрос (>150 слотов) |
| 2   | DuplicateWithdrawal      | Повторное использование nonce     |
| 3   | NonceListFull            | Достигнут лимит в 100 nonce       |
| 4   | InvalidRecipient         | Несоответствие адреса получателя  |

## Безопасность

1. **Защита ключа сервера**  
   Приватный ключ должен храниться в HSM/KMS-решении

2. **Мониторинг nonce**  
   Реализуйте систему отслеживания использованных nonce

3. **Валидация получателя**  
   Проверяйте адреса получателей перед подписанием

4. **Временные окна**  
   Сервер должен отклонять запросы с будущими слотами
